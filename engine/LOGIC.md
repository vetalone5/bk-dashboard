# Логика дашборда: данные, расчёты, правила

## 1. Четыре измерения

Каждая строка данных («запись») — это одно размещение или одна строка расхода.
У неё всегда есть четыре координаты. Не путать их между собой:

| Измерение | Что это | Значения |
|---|---|---|
| **Площадка** | где произошёл заказ | Wildberries, Ozon, Сайт trigger-fish.ru, Авито, Бот |
| **Канал** | откуда пришёл трафик | MAX, VK, Telegram, YouTube, Instagram, TikTok, Rutube, Внутренняя реклама WB, Внутренняя реклама Ozon |
| **Активность** | какая механика | Инфлюенс-посев, Внутренняя реклама, Авито, SEO-продвижение, Конкурс репостов в ВК, Свой YouTube-канал, Органика, Самовыкупы, Бартер, Таргет ВК, Контекст |
| **Продукт** | что продаём | Amino Trigger Fish, Аппликатор Ярмакова, Бот «Зелёный доктор», Бот «Умный сад», Бот «Клёвое место» |

Авито — это площадка продаж, у которой внутренняя реклама идёт как канал.
Органика и Самовыкупы — служебные активности, в фильтре каналов их нет.

## 2. Тип: товары и боты

Фильтр «Тип» делит всё на товары / боты / всё.

- **Товары** считаются в заказах: CPO (расход ÷ заказы), выкупы, выручка, сумма заказов, средний чек, ДРР.
- **Боты** считаются в регистрациях: CPA (расход ÷ регистрации). Заказов у ботов нет.
- **Заказы и регистрации никогда не суммируются.** Это разные сущности.

Куда ведёт размещение — определяется колонкой «Продукт» в таблице менеджера.
Отдельной колонки под боты не нужно: если в продукте написано «Зелёный доктор»,
«Умный сад» или «Клёвое место» — это бот.

Бюджет ботов при этом остаётся в общем расходе и участвует в общем CPO/ДРР.
Это сделано сознательно: боты делаются ради продвижения товаров, и так видно,
как весь бюджет распределяется.

## 3. Структура данных внутри

Каждая запись хранит массив из 5 недель. Каждая неделя — 8 чисел:

```
[ расход, заказы, выкупы, выручка, клики, размещений, сумма заказов, регистрации ]
   0        1       2       3        4      5           6              7
```

Поля записи: месяц, продукт, площадка, канал, активность, название размещения,
ссылка, дата, тип метки, менеджер, недели, признак «оценка» (est), источник (src).

Признак **est** значит, что цифра — оценка менеджера, а не факт из API.
Где метка Ozon совпала — ставится факт из API и est снимается.

## 4. Метки и атрибуция

Тип метки (tag) у размещения:
- `art` — подменный артикул WB (начинается на WW)
- `promo` — промокод
- `utm` — UTM-метка
- `none` — метки нет, отдача только со слов менеджера
- `sys` — служебная строка

**Ozon.** Три формата ссылок в таблицах менеджеров:
1. Короткая: `ozon.onelink.me/SNMZ/xxxxxxxx` — надо раскрыть через браузер (WebFetch не работает, отдаёт ROBOTS_DISALLOWED) и достать `utm_campaign` из итогового адреса. Раскрытые лежат в `data/api/shortlinks.json`.
2. Длинная onelink с параметром `c=` — метка лежит в `c=`.
3. Прямая `ozon.ru/...?utm_campaign=` — метка в явном виде.

Метку искать **по всему телу ссылки**, а не только по хвосту. Менеджеры оформляют
по-разному, и часть меток теряется, если смотреть только конец строки. Это главная
причина «не нашёл метч» — проверять всегда.

**Проблема повторных меток.** У Марии одна общая кампания `vendor_org_4202727`
на девяти размещениях, `_max` на трёх, `_sakhahunter` на двух. По кампании их
не разделить. Решение: запрашивать внешний трафик Ozon в трёх разрезах —
`group_by=campaign`, `group_by=content`, `group_by=term` — и матчить по тому,
который уникален. Приоритет: уникальная кампания → content → term → общая кампания.
У Елены метки уникальные, ей хватает кампании.

**Wildberries.** Отдачу от посева по API получить нельзя: подменных артикулов
и внешнего трафика в API WB нет ни при каких правах. Только кабинет
(«Рост продаж → Подменные артикулы») или оценки менеджера.

## 5. Что берём из API, а что нет

Берём:
- итоги по заказам, выкупам, суммам заказов (WB — воронка, Ozon — заказы)
- выручка = сумма выкупленных товаров (не выплата продавцу)
- суммы **без СПП** — цена товара до скидки площадки. Это расчётная база для комиссий. Для справки: август, Ozon — 932 630 ₽ без СПП против 519 216 ₽ «по цене реализации»
- заказы по размещениям — по UTM-меткам Ozon, приоритет у факта API над оценкой менеджера
- рейтинг карточек
- внутренняя реклама (расходы кампаний)

Не берём: отмены, корзины, поисковые запросы, отзывы, комиссии, цены.

**Клики** остаются из таблиц менеджеров (Мобзио, WB) — в API их нет.

Правило стыковки: где метки Ozon совпали — ставим факт API и снимаем «оценку».
Где не совпали — оставляем оценку менеджера, помечая её как оценку.

## 6. Органика

В таблицах органики нет. Она считается вычитанием, по месяцу:

```
органика = факт площадки − внутренняя реклама − инфлюенс-посев − самовыкупы
```

Потом результат распределяется по неделям пропорционально недельному факту площадки.

## 7. Пороги и цвета

**CPO зависит от продукта** — у аппликатора другой средний чек:

| Продукт | зелёный | жёлтый | красный |
|---|---|---|---|
| Amino Trigger Fish | до 200 ₽ | 201–400 ₽ | выше 400 ₽ |
| Аппликатор Ярмакова | до 800 ₽ | 801–2000 ₽ | выше 2000 ₽ |

**CPA ботов**: зелёный до 130 ₽, жёлтый 130–250 ₽, красный выше.

**Блок «Лучшие по CPO»**: показывает все размещения, попавшие в зелёный порог.
Если их меньше 20 — добирает следующими по дешевизне, чтобы блок не был пустым.
Для ботов сортировка идёт по регистрациям и CPA, а не по заказам.

**Средний чек** — плитка, которую дашборд считает сам: сумма заказов ÷ заказы.
Только для товаров, кликабельна — раскрывает динамику по неделям.

## 8. План

План берётся **только** из общего медиаплана: файл `05_mediaplan.xlsx`,
лист «План упрощённый». Планы во вкладках менеджеров не используются как источник.

Структура листа: строки — продукты и статьи, колонки — месяцы (июль…декабрь).

Важное ограничение: в медиаплане **нет разбивки по площадкам, каналам и менеджерам**.
Поэтому:
- блок плана виден всегда, даже при нулевом факте;
- он реагирует на фильтры месяца, типа, продукта и активности;
- при включённом фильтре площадки, канала или менеджера показывается предупреждающая
  плашка: план в этом разрезе не существует.

Ещё одно: в медиаплане **нет строки органики** — он построен от бюджета.
Поэтому план сравнивается с фактом платных каналов, а органика показывается
«сверх плана». Иначе выполнение плана раздувается.

Агрегировать план по площадке можно только если у всех её каналов план есть.
Иначе получается фальшивая картинка вроде «Wildberries 217% плана», где план был
только у внутренней рекламы.

## 9. KPI инфлюенс-менеджеров

Премия 50 000 ₽, делится по трём KPI. Новые уровни не придумывать — какие есть, такие есть.

| KPI | Вес | Уровни |
|---|---|---|
| 1. Сроки | 0,1 | коэффициент 0,1 / 0,4 / 1 — ставится вручную селектом |
| 2. Цена клика (CPC) | 0,5 | >150 ₽ → 0,2; 101–149 ₽ → 0,5; 80–100 ₽ → 0,7; <80 ₽ → 1 |
| 3. CPV | 0,4 | >1,3 → 0,1; 1,1–1,3 → 0,5; 0,5–1,0 → 0,7; 0,3–0,49 → 1 |

**Окна расчёта:**
- первый месяц работы сотрудника — публикации с 1 по 17 число;
- дальше — с 18 числа предыдущего месяца по 17 число текущего.

Елена: первый месяц — август. Мария: первый месяц — июль.

**CPC считается только по Мобзио** и только по тем размещениям, где ссылка была
и клики есть. Размещения без ссылки в расчёт CPC не идут.
CPV — по размещениям, где есть охват.

**Проверка формул.** Дашборд не пересчитывает KPI 1 и не правит таблицы.
Он показывает только ошибки в самих таблицах: сравнивает итоговые строки
(«Итого: неделя…» и «ИТОГО ЗА МЕСЯЦ») с суммой строк-деталей по колонкам
расход / охват / клики Мобзио / клики WB / заказы / выкупы / выручка / сумма заказов.
Расхождение больше 1 единицы или 1% — считается ошибкой формулы и выводится списком.

## 10. Сценарий рекламы

В таблицах менеджеров есть колонка со сценарием рекламы. Мария её заполняет,
Елена — нет. В дашборде сценарий показывается маленьким маркером в блоке
«Лучшие по CPO», чтобы видеть, какие сценарии дают дешёвые заказы.

## 11. Что известно про эффективность (по данным на сентябрь 2026)

Это выводы, а не правила — но они помогают проверять, что сборка не врёт.

- Снижение CPO и ДРР по компании — это эффект микса, а не роста эффективности:
  доля органики выросла с 19% до 62%. Сам посев при этом дорожал: CPO 791 → 2 230 → 4 166 ₽.
- По Amino Trigger Fish лучший канал — MAX: средний CPO 437 ₽, 53% заказов на 19% бюджета.
  Худший — VK: 3 311 ₽ при самом большом бюджете.
- Площадка важнее канала: связка MAX → Wildberries даёт 151 ₽ за заказ,
  MAX → сайт — 2 373 ₽.
- Сверка оценок менеджеров с фактом Ozon: из 17 проверенных совпали ровно 9.
  Самое большое расхождение — `vanorybak`: оценка 1 заказ, факт 8.

## 12. Известные ограничения

- Заказы с сайта trigger-fish.ru (Tilda) не выгружаются. В API Tilda нет заказов,
  только контент — заказы можно получить либо выгрузкой CSV из Tilda CRM,
  либо вебхуком формы (UTM подтягиваются автоматически через куку `TILDAUTM`,
  товары и сумма требуют донастройки). Пока в дашборде стоит служебная строка «нет данных».
- У Ozon по сути два SKU (одиночная бутылка и комплект из двух). Сейчас они
  суммируются в один продукт. Разделить можно, пока не сделано.
- Контентный рейтинг карточек Ozon доступен в API, но в дашборде не выводится.
