Качество атрибуции и расхождения в таблицах

Доли считаются по потраченному бюджету. UTM-ссылка на карточку Wildberries меткой не считается — WB её не видит: там работает только уникальный поисковый артикул (WW…) или промокод. На Ozon работает ссылка с utm_campaign=vendor_org. Мобзио даёт клики, но заказы не привязывает.

Каких данных не хватает что доберём, когда подключим API

Список того, что сейчас либо считается вручную, либо не считается вовсе. Красное — блокирует расчёт, оранжевое — искажает, серое — мелочи и ручная работа.

🔴
Ozon Seller API — ключа нетНе хватает: заказы, выкупы и выручка по SKU и датам, расход и статистика внутренней рекламы, органика, общее число заказов для контрольной суммы. Сейчас всё это берётся из таблиц Марии и Елены и из отчёта Анастасии.
🔴
WB: отчёт по поисковым запросамБез него подменные артикулы (WW…) не привязываются к заказам автоматически. Метод в API есть, но раздел требует подписки Джем — надо проверить, оплачена ли она. Ограничения: топ-30 запросов на товар и максимум 7 суток за один запрос, то есть тянуть надо еженедельно.
🔴
Сайт: заказы ТильдыЕсть клики по UTM, но выручка и заказы по меткам не выгружаются — UTM не сохраняется в самом заказе. Из-за этого ДРР по сайту считается по обрывочным данным.
🟠
Отчёты Ани (июнь–июль): нет выкупов и выручкиЕсть только заказы и «сумма заказов» до выкупа. ДРР по июню и июлю не считается. Добирается из API WB по датам и артикулу 1024637244.
🟠
WB: воронка по карточкамПереходы в карточку и добавления в корзину есть только там, где менеджер вёл их вручную. Метод nm-report в API это закрывает — тогда появятся клики и корзины по всем размещениям, а не по части.
🟠
WB: расход внутренней рекламыСейчас из отчёта Анастасии, руками. Через API рекламы будет автоматом и по дням, а её таблица останется только источником плана.
🟠
Финансовый отчёт WBНет комиссий, логистики и возвратов, поэтому ДРР считается от валовой выручки, а не от денег, которые реально пришли. Метод reportDetailByPeriod.
🟠
Остатки на складахНе видно, был ли товар в наличии в день выхода публикации. Без этого нельзя отличить «блогер не сработал» от «товара не было».

Откуда берутся данные сейчас и как должно быть

Сейчас почти всё считается из таблиц менеджеров, потому что ключа Ozon API ещё нет, а коннектор Wildberries отдаёт только сводки. Правый столбец — целевая схема: цифры продаж тянем из API площадок, а из таблиц берём только то, чего в API нет физически — метки, расход и клики.

ДанныеОткуда берутся сейчасОткуда должны браться
Заказы — итог площадкиИз API обеих площадок за весь период. Wildberries — воронка продаж, июнь–сентябрь. Ozon — заказы, август–сентябрь (раньше площадки не было: внешнего трафика до августа Ozon не фиксирует вообще)Автообновление раз в сутки вместо ручного запуска
Средний чекСчитается дашбордом: сумма заказов ÷ количество заказов. Вручную нигде не вбивается. База — цена до скидки площадки, поэтому чек выше того, что покупатель платит на кассе. По ботам не считаетсяРазделить два SKU на Ozon (одиночная банка и комплект 2 шт) — сейчас они в одном продукте, и чек смешанный: в августе одиночная 947 ₽, комплект 1 776 ₽
Сумма заказов: с СПП или безБерём БЕЗ СПП — цену до скидки площадки. Это расчётная база, от которой Ozon и WB считают свои комиссии и хранение. За август по Ozon это 932 630 ₽ (чек 1 001 ₽), а не 519 216 ₽ из выгрузки по цене реализации (чек 532 ₽) — разница и есть скидка площадки за её счёт. Отчёт Ozon по внешнему трафику отдаёт суммы в той же базе, без учёта акций, поэтому блогерские суммы и итог площадки сопоставимыТак и оставляем
Заказы — по размещениям OzonФакт из API по метке — строка помечена плашкой «факт API». Метка ищется в трёх разрезах отчёта Ozon: campaign, content и term, потому что менеджеры кладут её по-разному. Короткие ссылки ozon.onelink.me раскрываются до полной, длинные читаются по параметру c=. Метка ищется по всему телу ссылки, а не только по хвосту — менеджеры размечают по-разному. Все 35 Ozon-размещений за август и сентябрь связаны с фактомПравило для менеджеров: у каждой интеграции своя метка, различимая хотя бы в одном из полей campaign, content, term. При проверке сверять всё тело метки целиком
Заказы — по каналам и блогерам WB и сайтаОценка из таблиц менеджеров, проставляется вручнуюПо WB — воронка по nmId подменного артикула. По сайту — выгрузка заказов Тильды с UTM
ВыкупыWildberries — API (свежее выгрузки: август 529 против 491 в файле). Ozon — выгрузка. По каналам — оценка менеджеровOzon тоже на API
ВыручкаWildberries — API: сумма выкупленных товаров, а не «к выплате». Средний чек выкупа считается как сумма выкупов ÷ количество выкупов. Ozon — выкупы × чек из выгрузкиOzon тоже на API, по той же логике — сумма выкупленного, не к выплате

Добавления в корзинуРешено пока не тянуть. В API есть: WB август 2 664 корзины, Ozon по меткам 795Вернуться позже
Внутренняя реклама: расход, заказы, суммаAPI Wildberries (июнь–сентябрь) и Ozon (август–сентябрь). За июнь строки в отчёте Анастасии не было вообще — завели по API: 2 246 ₽ и 17 заказов. Недельная разбивка сохраняется по сетке Анастасии, месячные итоги подменяются на API. Август WB: было 43 731 ₽ и 267 заказов у Анастасии, API даёт 49 124 ₽ и 269. Рейтинг карточекИз API площадок. Wildberries отдаёт рейтинг по каждому SKU вместе с воронкой продаж, Ozon — в оценке продавца (ozon_rating). Значение ставится точкой на текущую неделю: на 08.09.2026 Ozon 4.9, WB 4.7 по активатору и 4.9 по аппликатору. Недели до этого остались из отчёта Анастасии — историю рейтинга площадки не отдают, задним числом её не восстановитьТак и работает. Вручную Анастасии заполнять больше не нужно — обновляется вместе с остальными данными
Контент-рейтинг карточек OzonЕсть в API, пока не выведен в дашборд. На 08.09: активатор 250 мл — 87,5 из 100 (не хватает аннотации 100–500 знаков и Rich-контента), комплект 2 шт — 69,5 (нет видео, мало изображений, та же аннотация)Вывести отдельной строкой рядом с рейтингом по отзывам — это разные вещи: одна про качество заполнения карточки, вторая про оценки покупателей
Сценарий рекламыКолонка «Сценарий рекламы» в таблицах менеджеров. Заполняет только Мария (номер сценария или название, например «Бабушки»), у Елены колонка пустаяОбязательное поле у всех менеджеров с единым справочником сценариев, чтобы сравнивать CPO между сценариями, а не только между блогерами
«Лучшие» и «Слив бюджета» — как считаютсяОдна строка = одна публикация из таблицы менеджера за выбранный период, никакой группировки по блогеру. «Лучшие» — CPO = «Итого к оплате» ÷ «Заказы» той же строки, порог 400 ₽, сортировка по возрастанию. «Слив бюджета» — те же строки, топ-20 по самому дорогому CPO, включая размещения с нулём заказов. В фильтре продукта-бота оба блока переключаются на регистрации и CPA, порог 250 ₽Заказы и регистрации по каждой публикации из API площадки и из бота по её метке — тогда оба рейтинга перестанут зависеть от того, как менеджер оценил результат
Активность — четвёртое измерениеИз медиаплана: инфлюенс-посев, внутренняя реклама, Авито, SEO-продвижение, конкурс репостов в ВК, свой YouTube-канал, плюс служебные — органика и самовыкупы. Активность отвечает на вопрос «какая механика», площадка — «где произошёл заказ», канал — «откуда пришёл трафик»Менеджеры проставляют активность в своих таблицах. Пока проставляется автоматически: всё из таблиц инфлюенса — посев, отчёт Анастасии — внутренняя реклама и самовыкупы
Плановые активности без фактаАвито заведена площадкой с каналом «Внутренняя реклама Авито» — план есть, факта нет. SEO, конкурс репостов в ВК и свой YouTube-канал видны в блоке «План месяца» и в фильтре активностей: у них есть бюджет, но площадка назначения пока неизвестнаОтчёт по Авито (заказы и расход), Метрика и Search Console по SEO, отчёт по конкурсу и статистика своего YouTube-канала. Как появятся — привяжутся к своей площадке
Пороги CPO по продуктамРазный средний чек — разные пороги. AMINOTRIGGERFISH: зелёный до 200 ₽, жёлтый 200–400 ₽, красный выше 400 ₽. Аппликатор Ермакова: зелёный до 800 ₽, жёлтый 801–2000 ₽, красный выше 2000 ₽. Боты — CPA: зелёный до 130 ₽, жёлтый 130–250 ₽, красный выше. При фильтре «Все продукты» в таблицах действуют пороги AMINOTRIGGERFISH, а в блоках «Лучшие» и «Слив бюджета» каждая строка красится по своему продуктуПороги задаются вручную. Правильнее считать их от юнит-экономики: целевой CPO = маржа × допустимая доля рекламы, по каждому продукту отдельно
Заказы и регистрацииДве независимые метрики, никогда не складываются. Заказы и CPO — у товаров, регистрации и CPA — у ботов. Сквозные метрики, которые суммируются по всему: бюджет, размещения, кликиКогда бот начнёт приводить продажи, заказы из бота встанут в товарный контур с активностью «бот» и своей площадкой (WB, Ozon или сайт)
Органика в планеМедиаплан построен от бюджета: заказы = бюджет ÷ целевой CPO. У органики бюджета нет, поэтому строки в плане нет, а плановое «Итого заказов» — это только платные каналы. В блоке «План месяца» факт считается тоже по платным, органика вынесена строкой «сверх плана»Так и оставить: органика — это результат, а не статья бюджета. В плитках сверху органика входит в общие заказы, её можно скрыть фильтром «Органика»
Площадка продаж, когда колонка пустаяЕсли «Канал продаж» у менеджера не заполнен, площадка определяется по метке: артикул на WW — Wildberries, ссылка с ozon — Ozon, ссылка на trigger-fish — сайт. «Не указано» остаётся, только если нет ни одной зацепкиОбязательное поле «Канал продаж» у всех менеджеров
План — весьТолько общий медиаплан «Медиаплан_Маркетинг», лист «План упрощённый»: бюджет, заказы, выручка, продукты и каналы. Медиапланы в таблицах менеджеров как источник плана не используются — они не сходятся с общим (август: 34 034 заказа против 13 205 в сумме у менеджеров)Тот же файл, но с разбивкой плана по менеджерам на каждый месяц — сейчас такой блок есть только под один выбранный месяц
Регистрации в боте«Зелёный доктор» — колонка «Запустили бота» в отчёте Ани (июнь–июль). «Умный сад» — колонка «Кол-во регистраций» в файле закупки Татьяны (март–май), привязка по метке startapp=src_*Выгрузка из самого бота по метке источника, с датой регистрации — тогда регистрации встанут по неделям точно, а не по дате выхода публикации
Продукт размещенияКолонка «Продукт» в таблицах менеджеров. Пустая ячейка = AMINOTRIGGERFISH. Продукт определяет, что считать результатом: заказы для товаров, регистрации для ботовОбязательное поле у всех менеджеров со справочником: AMINOTRIGGERFISH, Аппликатор, Бот «Зелёный доктор», Бот «Умный сад», Бот «Клёвое место»
План«Медиаплан_Маркетинг» — общие цифры, медиапланы менеджеров — по каналамТо же самое, но с разделением плана на Wildberries и Ozon отдельно
